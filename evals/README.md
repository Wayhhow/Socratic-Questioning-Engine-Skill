# 评测体系（Evals）

本技能自带一套"冒烟测试 + 自动评分"体系，任何 agent（或人）都可以复现。

## 组成

| 文件 | 作用 |
|:---|:---|
| [evals.json](evals.json) | 6 个测试场景：正向（概念理解、决策两难、卡住求支架）+ 边界（直接要答案、情绪危机、事实查询） |
| [rubric.md](rubric.md) | 10 维评分标准，含权重与 0–5 分锚点 |
| [grader.md](grader.md) | 评分 agent 的完整指令——把对话记录交给它，即可自动评分 |

## 如何运行一次冒烟测试

1. **执行**：启动一个子代理，给它安装好的技能（SKILL.md 路径），让它扮演"装了本技能的助手"。逐轮喂入场景脚本中的用户发言，收集完整对话记录。
2. **评分**：启动另一个子代理作为评分员，向它提供 [grader.md](grader.md) + [rubric.md](rubric.md) + 对话记录 + 对应场景脚本。评分员输出 JSON 评分。
3. **判定**：加权总分 ≥ 4.2 且无任何适用维度 ≤ 2 分 → 通过；否则小修或迭代。

## 场景设计原则

- **正向场景**验证核心循环：复述→追问→递进→顿悟归属→元认知收束。
- **边界场景**验证克制：本技能最重要的性能是"知道何时不问"。事实查询不该触发追问剧场，情绪危机不该被分析，用户要答案时不应被绑架继续思考。
- 每个场景的 `assertions` 都是评分员可在对话记录中直接核验的陈述句。
